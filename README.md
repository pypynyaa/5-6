# Лабораторная работа №6: Клиент-серверное приложение

## Вариант 52352

## Описание проекта

Данный проект представляет собой клиент-серверное приложение для управления коллекцией объектов. Проект разделен на три модуля:
- `client` - клиентский модуль
- `server` - серверный модуль
- `common` - общие классы и интерфейсы

## Требования к реализации

### Общие требования
- Операции обработки объектов коллекции реализованы с помощью Stream API и лямбда-выражений
- Объекты между клиентом и сервером передаются в сериализованном виде
- Объекты в коллекции отсортированы по имени
- Клиент корректно обрабатывает временную недоступность сервера
- Обмен данными осуществляется по протоколу TCP
- Сетевые каналы используются в неблокирующем режиме

### Серверный модуль
Обязанности:
- Работа с файлом, хранящим коллекцию
- Управление коллекцией объектов
- Назначение автоматически генерируемых полей объектов
- Ожидание подключений и запросов от клиента
- Обработка полученных запросов (команд)
- Сохранение коллекции в файл при завершении работы
- Сохранение коллекции по специальной команде

Структура серверного приложения:
- Модуль приёма подключений
- Модуль чтения запроса
- Модуль обработки полученных команд
- Модуль отправки ответов клиенту

Сервер работает в однопоточном режиме.

### Клиентский модуль
Обязанности:
- Чтение команд из консоли
- Валидация вводимых данных
- Сериализация введённой команды и её аргументов
- Отправка команды и аргументов на сервер
- Обработка ответа от сервера

Особенности:
- Команда `save` отсутствует в клиентском приложении
- Команда `exit` завершает работу клиентского приложения
- Команды и их аргументы представлены в виде объектов классов

### Дополнительное задание
Реализовано логирование различных этапов работы сервера с помощью Log4J2:
- Начало работы
- Получение нового подключения
- Получение нового запроса
- Отправка ответа
- и т.п.

## Запуск проекта

### Сервер
```bash
cd server
mvn clean package
java -jar target/server-1.0-SNAPSHOT.jar
```

### Клиент
```bash
cd client
mvn clean package
java -jar target/client-1.0-SNAPSHOT.jar
```

## Доступные команды
- `help` - вывести справку по доступным командам
- `info` - вывести информацию о коллекции
- `show` - вывести все элементы коллекции
- `add` - добавить новый элемент
- `update id` - обновить элемент по id
- `remove_by_id id` - удалить элемент по id
- `clear` - очистить коллекцию
- `execute_script file_name` - выполнить скрипт из файла
- `exit` - завершить программу
- `remove_greater` - удалить элементы, большие заданного
- `remove_lower` - удалить элементы, меньшие заданного
- `history` - показать историю команд
- `remove_all_by_soundtrack_name name` - удалить элементы по названию саундтрека
- `filter_greater_than_car` - вывести элементы с машиной лучше заданной
- `print_descending` - вывести элементы в порядке убывания
- `save` - сохранить коллекцию в файл

## Модель данных
Класс `HumanBeing` содержит следующие поля:
- `id` - уникальный идентификатор
- `name` - имя (не может быть null)
- `coordinates` - координаты
- `creationDate` - дата создания
- `realHero` - является ли героем
- `hasToothpick` - есть ли зубочистка
- `impactSpeed` - скорость удара
- `soundtrackName` - название саундтрека
- `minutesOfWaiting` - минуты ожидания
- `weaponType` - тип оружия
- `car` - машина

